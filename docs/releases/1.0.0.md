# New Rally-X for MSX — 1.0.0

**One ROM. Automatic mapper and turbo detection. The original 64 KiB machines remain supported.**

This release brings the optimized SCREEN 4 game to a single ASCII16 cartridge. There is no need to choose between separate 64 KiB and 128 KiB downloads: the game checks the machine at startup and selects the appropriate cache and supported CPU acceleration automatically.

## Compatibility and automatic hardware selection

- **Target:** MSX2+ / V9958, at least **64 KiB RAM with the standard RAM-mapper interface**, and 128 KiB VRAM. MSX turboR is also covered by emulator qualification. This is not an MSX1 release or a claim that every MSX2 configuration is qualified.
- **64 KiB:** retains the compact radar-cache strategy and full game functionality.
- **128 KiB or more:** automatically selects the expanded radar cache. Stock FS-A1ST/GT configurations report their actual 256/512 KiB capacities.
- **Panasonic FS-A1FX, FS-A1WX and FS-A1WSX:** uses their factory software-controlled Z80 acceleration, nominally 3.58 to 5.37 MHz, for selected CPU work.
- **Panasonic FS-A1ST and FS-A1GT:** uses the supported R800 ROM backend for selected CPU work.
- **Machines without a supported turbo backend:** safely retain normal Z80 operation. A larger RAM mapper does not require turbo, and turbo does not require a separate cartridge image.

The initial hardware-check screen displays `ROM OK`, `MAPPER <capacity>K` and `TURBO ON/OFF`. Turbo ON indicates that the supported acceleration backend is available; video/audio/I/O timing and original game clocks remain protected. This is separate from emulator fast-forward or arbitrary CPU overclock settings.

## Measured performance

Performance is measured in **presented gameplay frames per second**, separately from the 60 Hz display refresh. The target is approximately 30 presented FPS; a higher CPU clock does not mean every VDP-limited frame becomes faster.

Factory-turbo paired workloads on the Panasonic targets reduced **mean elapsed work by 7.16–15.36%**; p95 improved in every measured pair. Examples from the FS-A1WSX with 64 KiB:

| Native enemies | Base CPU | Automatic turbo | FPS gain |
| --- | ---: | ---: | ---: |
| 3 | 29.468 FPS | 29.966 FPS | 1.69% |
| 5 | 27.997 FPS | 28.872 FPS | 3.13% |
| 6 | 27.431 FPS | 28.701 FPS | 4.63% |

On the WSX six-enemy workload, late presentations fell from **17.65% to 8.82%**. The recorded turboR ST six-enemy comparison improved from **27.431 to 29.111 FPS** (6.12%). Those ST rows describe a forced compact-cache diagnostic on the machine's actual stock RAM, not an assertion that an ST has only 64 KiB.

With turbo already enabled, the larger mapper cache reduced **mean work by 0.58–2.79%** and **p95 by 2.46–5.49%** across the nine FX/WX/WSX comparisons. On the WSX:

| Native enemies | 64 KiB cache tier | 128 KiB+ cache tier |
| --- | ---: | ---: |
| 3 | 29.966 FPS | 30.029 FPS |
| 5 | 28.872 FPS | 28.872 FPS |
| 6 | 28.701 FPS | 28.993 FPS |

The five-enemy cache comparison has unchanged FPS: less work does not always cross a presentation boundary. CPU and mapper percentages must not be added together. These same-input workloads can follow different trajectories; they are not a fixed speedup promise for an entire game. Five historical turbo pairs had increased worst-case work despite improved mean/p95, with the largest increase 11.80%.

The complete CPU/cache matrices precede the final logo-only update and retain their original ROM hashes. The final image reproduces the WSX 64 KiB three-enemy profile at 29.966 FPS. The [performance evidence](../issue39-software-turbo.md) and [timing ledger](../measurements/timing/cycle-ledger.json) identify the measured ROM and workload for every claim. Physical hardware was unavailable; these are openMSX results, not physical-machine certification or a new subjective audio acceptance claim.

## Download and play

Download **`newrallyx.rom`** from this release. Use cartridge type **ASCII16** in every emulator. The same file is used on 64 KiB machines, expanded machines and supported turbo systems.

### WebMSX

[Play 1.0.0 in WebMSX — MSX2+, 128 KiB, ASCII16](https://webmsx.org/?M=MSX2PJ&P=RAM128&ROM=https%3A%2F%2Fgithub.com%2Fsandersouza%2Fmsxgp-newrallyx%2Freleases%2Fdownload%2F1.0.0%2Fnewrallyx.rom&ROM_FORMAT=ASCII16)

The link requests the release ROM, a generic MSX2+ with 128 KiB, and explicitly forces `ROM_FORMAT=ASCII16`. Click the emulator to give it keyboard focus and enable audio if the browser requests interaction. A generic MSX2+ is not a model of Panasonic's Z80 turbo hardware; turbo OFF there is expected. A turboR machine can be selected separately, but WebMSX timing is not the basis of the measurements above.

For manual loading, open [WebMSX](https://webmsx.org), choose MSX2+ or turboR, insert `newrallyx.rom` in cartridge slot 1 and force **ASCII16** in the cartridge-format controls. The URL/format options follow the [official WebMSX documentation](https://github.com/ppeccin/WebMSX/blob/master/doc/README.md#media-loading).

### openMSX

Choose a supported MSX2+ or turboR machine and load the cartridge with explicit mapper type, for example:

```sh
openmsx -machine Panasonic_FS-A1WSX -cart newrallyx.rom -romtype ASCII16
```

Supply the required BIOS locally. From the source checkout, `make run` builds the ROM and launches the 64 KiB reference; `make run MAPPER=1` launches the **same ROM** with 128 KiB. No separate turbo build is required. Leave emulator speed at normal for comparison with the measurements.

### Controls

**5:** insert credit. **1:** one player. **2:** alternating two-player game (two credits). **Arrow keys / joystick 1:** steer. **Space / Ctrl / trigger A:** smoke. **P:** pause.

## A reusable MSX port laboratory

The runtime and host tools now have separate homes: `src/screen4`, `src/screen5` and `src/toolchain`. The repository preserves reusable techniques, assembly contracts, comments, synthetic tests and compact measurements rather than gigabytes of discarded experiments.

After supplying the original unpacked arcade set in `references/roms/nrallyx/`, `make build` and normal `make run` automatically prepare missing graphics, captures, reconstructed scenes, native-state inputs and the original 56x8 Namco wordmark. `make extract-all` exposes the same preparation explicitly. Original game data and BIOS remain local and ignored; the repository includes tools and empty reference-directory markers. See [first-build instructions](../building.md).

The supplied 54x20 monochrome MSX logo is imported at its intended 1:1 size. HUD, full car drawings, original scenery and gameplay/audio timing were retained without a new graphical reduction.

## Delivery checks and cartridge identity

- **ROM:** 2,048,000 bytes; 49,152 bytes below the 2 MiB hard ceiling.
- **SHA-256:** `d73539eb988b6de198a214bcb5e03476df903dec82fe78a53cc30ea9308ea963`.
- **Tests:** 467 general and 93 component tests; one documented component skip.
- **Reproducibility:** first build with assets/caches absent produced the same ROM; both reconstructed scenes had zero pixel mismatches.
- **Runtime:** current-image 64 KiB start/graphics and 128 KiB integration/graphics checks; broader earlier machine matrices remain documented under their own hashes.
- **Module layout:** preserved historical extraction image and all 1,589 symbols; zero module-boundary runtime overhead.
